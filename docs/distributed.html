Opt-in pipeline

Distributed training

A separate lifecycle for fixed-membership DDP across one or multiple machines. Existing single-GPU projects keep their classes, configurations, and behavior.

Choose the pipeline

Existing projects                    Distributed projects
JimmyExperiment                      DistributedJimmyExperiment
JimmyTrainer                         DistributedJimmyTrainer
JimmyModel                           DistributedJimmyModel
JimmyDataset                         DistributedJimmyDataset
python main.py                       torchrun ... distributed_main.py

New classes are exported by Distributed. The original classes do not import or initialize the new pipeline. Changing the base classes is an explicit opt-in; check custom training and dataset iteration against the contracts below.

Launch

# One machine, four visible GPUs
torchrun --standalone --nproc-per-node=4 distributed_main.py
# A reordered subset: physical identities in the dashboard remain correct
CUDA_VISIBLE_DEVICES=3,1 torchrun --standalone --nproc-per-node=2 distributed_main.py
# CPU smoke run or one-worker debugging
CUDA_VISIBLE_DEVICES="" torchrun --standalone --nproc-per-node=1 distributed_main.py

# Two machines, four GPUs each: execute on BOTH machines.
# Replace NODE_RANK with 0 on the primary machine and 1 on the other.
JIMMY_DASHBOARD_HOST=PRIMARY_HOST torchrun --nnodes=2 --nproc-per-node=4 \
  --node-rank=NODE_RANK --master-addr=PRIMARY_HOST --master-port=29500 \
  --max-restarts=0 distributed_main.py

PRIMARY_HOST must be reachable by both machines. Use matching PyTorch/CUDA environments, identical code, the same worker count per machine, and the same logical dataset/order. NCCL is used for CUDA and Gloo for CPU. This is ordinary replicated-model DDP, not model sharding. The example downloads MNIST once per machine; synthetic tests never download data.

Launch the dashboard on the primary machine: python -m Training.ExperimentManager --host 0.0.0.0 --port 9000. The example reads JIMMY_DASHBOARD_HOST; custom experiments set constants["progress_host"]. Use the server's actual port if it selects a different available port. Bind on a trusted network as described in the dashboard guide.

Configuration

from Distributed import DistributedJimmyExperiment

experiment = DistributedJimmyExperiment("My distributed run")
experiment.model_cfg.cls = MyDistributedModel
experiment.dataset_cfg.cls = MyDistributedDataset
experiment.dataset_cfg.batch_size = 32  # Per GPU
experiment.constants.update(n_epochs=20, progress_host="primary-host")
experiment.distributed_cfg.update(
    backend=None,                  # Automatic NCCL/CUDA or Gloo/CPU
    timeout_seconds=1800,          # Includes time waiting for rank-0 validation
    seed=0,
    data_prepare_scope="none",     # none, shared, per_node
)
trainer = experiment.start(checkpoint=None)

model_cfg, dataset_cfg, lr_scheduler_cfg, and training constants retain familiar roles. All ranks must use matching configurations. batch_size × world_size is the global batch size (the final batch may be smaller). Learning rates are never automatically scaled. BatchNorm statistics stay local to each GPU.

The experiment requires a torchrun environment, even with one worker. For a manual lifecycle, construct Distributed.Context.DistributedContext before datasets/models, move the model to context.device, call initialize(), and pass distributed_context=context to the new trainer. Close the context in a finally block. The trainer detaches its DDP wrapper on exit; an explicitly supplied context remains the caller's responsibility.

Keep the training methods

from Distributed import DistributedJimmyModel
from Models.Functional import getAutoCast

class MyDistributedModel(DistributedJimmyModel):
    # Define architecture in __init__, then implement forward as usual.
    def trainStep(self, batch):
        with getAutoCast(batch["data"], self.mixed_precision):
            prediction = self(batch["data"])
            loss = self.loss_fn(prediction, batch["target"])
        self.backwardOptimize(loss)
        return {"Train/Main": loss.item()}, {"output": prediction.detach()}

No computeTrainLoss hook is required. Training forwards must call self(...), not self.forward(...) or a detached inner network that bypasses DDP. Call self.backwardOptimize(loss) once per batch with a differentiable scalar loss. Return declared scalar mean metrics and detached outputs. Every rank must follow the same forward/backward sequence, with every trainable parameter participating in the loss.

The bridge runs DDP forward before returning to the training method. The backward dispatch guard checks loss finiteness collectively before calling your optimizer method. The default method handles AMP, synchronized backward, unscaling before clipping, optimizer update and gradient clearing. Custom backwardOptimize overrides remain supported and own those optimization details; overriding it does not automatically add AMP or clipping to your code. Bypassing the guarded method, independently skipping backward, accumulation, and multiple optimizer updates are outside this version's contract.

compile_model=True compiles the underlying forward. evalStep, testStep, and figure output are retained. The separate DistributedSampleCNN reuses the original architecture and evaluation hooks, supplying a corrected training method; the original SampleCNN remains untouched.

Data and preparation

from Distributed import DistributedJimmyDataset

class MyDistributedDataset(DistributedJimmyDataset):
    @classmethod
    def prepareData(cls, root, **dataset_args):
        # Optional download or preprocessing, before any split is constructed.
        ...

    def __getitem__(self, batch_idx):
        indices = self._indices[batch_idx * self.batch_size:
                                (batch_idx + 1) * self.batch_size]
        return {"data": self.features[indices], "target": self.targets[indices]}

Call the base constructor and set global n_samples in your constructor. The trainer configures global-rank partitioning and changes the deterministic shuffle each epoch. len(dataset) remains global; local_n_samples and n_batches are local. Standard inherited iteration/indexing works unchanged. A custom iterator must use the assigned _indices, honor setEpoch, and produce exactly n_batches dictionary batches.

With drop_last=False, pad the shuffled global index sequence to equal worker lengths; padding repeats samples intentionally. With drop_last=True, truncate evenly and discard incomplete local batches. Zero training steps are rejected. Tensors in nested dictionaries/lists/tuples move to the selected device; metadata is retained. The distributed prefetch loader propagates producer errors and stops its producer on normal exit or consumer failure.

none assumes data already exists everywhere. shared calls the dataset's prepareData(**dataset_args) only on global rank 0 before releasing workers. per_node calls it once on each local rank 0. Arguments exclude cls and set_name. All workers must see the same sample content and ordering; matching sample counts cannot prove content identity. Validation is constructed only on global rank 0. The new MNIST example uses disjoint 90%/10% training/validation splits and keeps source images in host memory.

Lifecycle and failure handling

torchrun workers
  → device selection + process group
  → worker identities + data preparation
  → model/dataset construction + initial parameter synchronization
  → training: DDP forward → collective finite check → backward/update
  → average metrics → smoothing → synchronized scheduler
  → global rank 0 validation + checkpoints → broadcast results
  → coordinated stopping → reporters/loaders/DDP cleanup

Only global rank 0 creates run metadata, SQLite logs, TensorBoard writers, figures, and best/last checkpoints. Other ranks receive the run identity and paths without opening those directories. Dashboard learning-rate requests are broadcast before updates and preserve the existing first optimizer-group behavior. Training metrics are averaged before smoothing; schedulers receive the same values. Validation retains per-batch averaging.

Checkpoint policy is unchanged: evaluate on epochs where epoch % eval_interval == 0, save best.pth on improvement and last.pth on each evaluation. Files contain ordinary unwrapped model weights. The distributed loader uses explicit device mapping and requires matching weight keys/shapes. It loads on rank 0 before DDP synchronization; other machines do not need access to that file. Optimizer, scheduler, RNG, and epoch state are not resumed.

Data/setup and primary-only errors are propagated across workers. Non-finite losses abort before backward. Communication has a finite timeout; torchrun terminates failed jobs. A custom method that stops participating in collectives may require that timeout. Fixed membership and --max-restarts=0 are the supported defaults; automatic elastic recovery is not implemented.

Machine-aware monitoring and verification

Global rank 0 owns training status and progress. One local-rank-0 reporter per machine samples every NVML-detected GPU in the background, with no distributed collectives. UUID matching respects CUDA visibility/order. Idle GPUs remain visible; unresolved assignments and unavailable readings are explicit. Resource cards are grouped by machine, while job progress is shown once. Old client payloads remain supported. See the payload and staleness guide.
