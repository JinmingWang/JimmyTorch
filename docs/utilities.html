Specialized utilities

JimmyTorch includes focused helpers for diffusion processes, geospatial trajectories, general sequences, and sliced 3D geometry.

Diffusion models and samplers

DiffusionModels exports DDPM, DDIM, DPM-Solver++, VP/VE Score-SDE processes, and a predictor-corrector sampler. The discrete models share schedule and prediction-conversion code; the continuous Score-SDE processes intentionally use a separate hierarchy.

DDPM and DDIM

DDPM and DDIM support linear, quadratic, logarithmic, and Improved-DDPM cosine schedules. Both accept predictions of x0, accumulated noise epsilon_0_to_t, or velocity v during denoising.

import torch
from DiffusionModels import DDIM

process = DDIM(
    min_beta=1e-4,
    max_beta=2e-3,
    max_diffusion_step=100,
    device="cpu",
    scale_mode="cosine",
    skip_step=5,
    eta=0.0,
)

x0 = torch.randn(4, 32)
t = torch.tensor([10, 20, 30, 40])
epsilon_0_to_t = torch.randn_like(x0)
xt = process.diffuse(x0, t, epsilon_0_to_t)
velocity = process.computeVelocity(x0, epsilon_0_to_t, t)

Noise names encode their dependency range: epsilon_t_to_tp1 is the single-transition noise, epsilon_0_to_t is accumulated noise at the current level, and epsilon_0_to_tp1 is the accumulated result after combining them. This distinction matters because the single-step and accumulated noises are dependent through the forward process.

The callable passed to denoise receives (x_t, t, **kwargs) and must return a three-item tuple (x0_pred, epsilon_0_to_t_pred, v_pred) with exactly one non-None prediction. The older epsilon_pred step keyword remains accepted for compatibility. Methods that sample noise accept a keyword-only PyTorch generator for reproducibility.

forward: clean -- beta[0] --> 0 -- beta[1] --> ... --> T-1
reverse: T-1 --> ... --> 1 --> 0 --> clean_timestep (-1)
Timestep endpoint changed.Index 0 is the first noisy state. The final transition is 0 → clean_timestep, where clean_timestep == -1. Direct calls using t_prev=0 receive a deprecation warning because older releases treated zero as clean data.

Primary references: DDPM, DDIM, and the Improved-DDPM cosine schedule.

DPM-Solver++

DPMSolverPP uses the same discrete schedule and three-item prediction callback as DDPM/DDIM. First-order updates are equivalent to deterministic DDIM. Second-order sampling reuses the preceding x0 prediction as multistep history, so it still requires only one model evaluation at each selected noise level.

With half-log-SNR lambda = log(alpha) - log(sigma) and h = lambda_previous - lambda_current, the first-order data-prediction update is x_previous = (sigma_previous / sigma_current) * x_current - alpha_previous * expm1(-h) * x0_pred. The second-order update adds the multistep correction from the difference between the current and preceding data predictions.

from DiffusionModels import DPMSolverPP

solver = DPMSolverPP(
    max_diffusion_step=1000,
    num_inference_steps=20,
    solver_order=2,
    device="cpu",
)

def predict(x_t, batch_timesteps):
    epsilon_0_to_t_pred = model(x_t, batch_timesteps)
    return None, epsilon_0_to_t_pred, None

# Generated schedule, e.g. 999 -> ... -> 0 -> clean_timestep (-1)
x0 = solver.denoise(initial_noise, predict)

# An explicit schedule is also accepted and must start at T-1 and end at 0.
x0 = solver.denoise(initial_noise, predict, timesteps=[999, 749, 499, 249, 0])

The stateless denoiseStep method is first order because a second-order multistep update requires a previous model prediction. The final 0 → clean_timestep transition returns the current data prediction directly, avoiding the infinite clean-endpoint log-SNR. Reference: DPM-Solver++.

Score-SDE

VPSDE and VESDE model continuous time in [0, 1]. They expose analytic drift/diffusion and marginal distributions, perturbation sampling, score targets, terminal-prior sampling, and convenience denoising. For x_t = mean(t) + std(t) * epsilon_0_to_t, computeScoreTarget returns -epsilon_0_to_t / std(t).

VP uses beta(t) = beta_min + t * (beta_max - beta_min), drift -0.5 * beta(t) * x, and diffusion sqrt(beta(t)). VE uses zero drift, sigma(t) = sigma_min * (sigma_max / sigma_min)^t, and diffusion sigma(t) * sqrt(2 * log(sigma_max / sigma_min)).

from DiffusionModels import PredictorCorrectorSampler, VPSDE

sde = VPSDE(beta_min=0.1, beta_max=20.0, device="cpu")
epsilon_0_to_t = torch.randn_like(x0)
continuous_timesteps = torch.rand(x0.shape[0]) * 0.999 + 0.001
x_t = sde.diffuse(x0, continuous_timesteps, epsilon_0_to_t)
score_target = sde.computeScoreTarget(epsilon_0_to_t, continuous_timesteps)

sampler = PredictorCorrectorSampler(
    sde,
    num_steps=1000,
    corrector_steps=1,  # use 0 for predictor-only sampling
    snr=0.16,
    epsilon=1e-3,
)

def score_func(noisy_samples, continuous_timesteps):
    return score_model(noisy_samples, continuous_timesteps)

initial_noise = sde.priorSampling((4, 32))
x0 = sampler.denoise(initial_noise, score_func)
forward perturbation: 0 (data) ------------------------------> 1 (prior)
reverse integration:  1 -- Euler/Langevin steps --> epsilon > 0

The positive terminal epsilon avoids the singular score limit at zero. It is a scalar time cutoff, not a noise tensor; perturbation noise retains the range-explicit name epsilon_0_to_t. The score callback always receives a batch-shaped continuous timestep tensor. All internal random draws accept a keyword-only PyTorch generator for reproducibility. Reference: Score-Based Generative Modeling through SDEs.

Trajectory utilities

Trajectory helpers operate on a single (L, 2) tensor or batched (B, L, 2) tensors where documented. The two coordinates are longitude and latitude for geographic distance functions.

General sequences

cropPadSequence(seq, target_len, pad_value=0.0) crops or pads along the first dimension and preserves the remaining feature dimensions. Unlike cropPadTraj, it is not restricted to two-coordinate trajectories.

3D mesh and slicing pipeline

The utilities in Datasets.ThreeDUtils form a geometry preprocessing pipeline:

01

Load and normalize

loadSTL, loadOFF, loadOBJ, or ASCII-only loadPLY, followed by normalizeMesh.

02

Slice and project

meshSlicing or meshSlicing_vectorized intersects triangle meshes with planes; projection helpers map intersections into 2D.

03

Rasterize or inspect

computeSDFImages creates signed-distance grids; build_figure produces an interactive Plotly view.

import torch
from Datasets.ThreeDUtils import (
    loadOBJ, normalizeMesh, meshSlicing,
    buildPlaneBasis, projectPointsTo2D,
)

triangles = loadOBJ("model.obj")
normalized, center, scale = normalizeMesh(triangles)
plane_axis = (0.0, 0.0, 1.0)
triangle_ids, slice_points, plane_centers, segments = meshSlicing(
    normalized,
    plane_interval=0.05,
    plane_axis=plane_axis,
)
basis = buildPlaneBasis(torch.tensor(plane_axis, device=normalized.device))
  • Mesh loaders return triangle vertices with shape (faces, 3, 3) as float32 tensors on their selected device.
  • OFF/OBJ polygon faces are fan-triangulated; PLY support is ASCII only.
  • computeSDFImages expects padded 2D segment tensors with explicit valid counts and always returns its result on CPU.
  • The SDF rasterizer chunks slices and pixel rows to bound accelerator memory.

Optional dependencies

loadSTL imports numpy-stl when reading an STL file. The OBJ, OFF, and ASCII PLY readers, mesh slicing, and projection work independently of that package. Install plotly to build interactive 3D figures and calflops to calculate FLOPs. See the installation guide for the training dependencies and other integrations.
