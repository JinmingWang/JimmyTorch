Dataset development

JimmyDataset is an iterable over batches, not a drop-in subclass of torch.utils.data.Dataset. A dataset owns splitting, optional shuffling, and the dictionary contract consumed by the model.

The contract

01

Call the base initializer

Pass set_name, batch_size, drop_last, and shuffle.

02

Set the sample count

After loading and selecting a split, assign the real value to self.n_samples.

03

Return a batch dictionary

__getitem__ receives a zero-based batch index and returns named values for that batch.

Minimal implementation

from typing import Literal
import torch
from Datasets import JimmyDataset, DEVICE


class MyDataset(JimmyDataset):
    def __init__(
        self,
        set_name: Literal["train", "eval", "test", "debug", "all"],
        batch_size: int,
        drop_last: bool = False,
        shuffle: bool = False,
    ):
        super().__init__(set_name, batch_size, drop_last, shuffle)

        all_inputs = torch.load("processed-data.pth", map_location=DEVICE)
        splits = {
            "train": slice(0, -300),
            "eval": slice(-300, -200),
            "test": slice(-200, None),
            "debug": slice(0, 100),
            "all": slice(None),
        }
        selected = splits[set_name]
        self.features = all_inputs["features"][selected].to(DEVICE)
        self.labels = all_inputs["labels"][selected].to(DEVICE)
        self.n_samples = len(self.features)

    def __getitem__(self, idx: int) -> dict:
        start = idx * self.batch_size
        end = min(start + self.batch_size, self.n_samples)
        indices = self._indices[start:end]
        return {
            "features": self.features[indices],
            "labels": self.labels[indices],
        }
Use descriptive keys.The framework does not impose input/target names. Stable domain names make model interfaces and debugging clearer.

Batching and iteration

MemberBehavior
n_batchesRecomputes the batch count from n_samples, batch_size, and drop_last.
__len__()Returns the number of samples, not the number of batches.
__iter__()Resets the batch cursor and creates self._indices, shuffled when requested.
__next__()Calls __getitem__ with batch indices 0..n_batches-1.

Because _indices is initialized by __iter__, iterate over a dataset—or call iter(dataset)—before invoking a custom __getitem__ that relies on it.

Queued preprocessing with MultiThreadLoader

JimmyTrainer wraps its training dataset in MultiThreadLoader. The loader uses one daemon producer thread and a bounded queue so CPU-side batch work can overlap model execution.

from Datasets import MultiThreadLoader

loader = MultiThreadLoader(train_set, queue_size=3)
for batch in loader:
    train_on(batch)

The constructor parameter is queue_size; it does not accept num_workers. Keep __getitem__ thread-safe and avoid using the loader when direct iteration is simpler.

Device and loading strategy

Datasets.DEVICE selects CUDA when available and CPU otherwise. The built-in MNIST dataset preloads tensors onto that device. Custom datasets may follow this GPU-first approach when their processed data fits in accelerator memory, but the base class itself does not move values or require every dataset to preload.

Memory is a dataset decision.Estimate the full split size before preloading. For large data, implement bounded loading deliberately and ensure the returned dictionary is on the device expected by the model.

Specialized data helpers

JimmyTorch exports trajectory transforms, sequence padding, 3D mesh loading and slicing, projection utilities, and signed-distance rasterization. See Specialized utilities for current names and constraints.

Opt-in distributed datasets

Use DistributedJimmyDataset for DDP. The trainer calls configureDistributed(rank, world_size, seed) and setEpoch(epoch). Global n_samples and batch-index __getitem__ remain; local_n_samples and n_batches describe each worker. Custom iterators must use the rank-local _indices and emit exactly that batch count. Padding repeats samples when drop_last=False; otherwise tails are dropped. The separate loader propagates errors and supports shutdown. Legacy dataset behavior is unchanged.
