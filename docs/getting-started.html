Getting started

Run the included MNIST example, understand what it creates, and then replace its dataset and model with your own.

Requirements

Run JimmyTorch from a source checkout. The repository currently has no pinned dependency manifest.

For the MNIST example, install a matching torch and torchvision pair for your platform. Then install the remaining training dependencies.

python -m pip install pandas matplotlib rich jaxtyping numpy

Optional dependencies

FeatureInstall when needed
Read STL meshesnumpy-stl. OBJ, OFF and ASCII PLY loading, slicing, and projection work with the training dependencies above.
Build interactive 3D figuresplotly
Count forward MACs and FLOPscalflops. Training can finish and save checkpoints when the profiler is unavailable.

1. Get the source

git clone https://github.com/JinmingWang/JimmyTorch.git
cd JimmyTorch

Run entry scripts from the repository root so imports such as from Models import ... and the default Runs/ path resolve correctly.

2. Start the optional monitor

Start one standalone service for the working directory. It serves the dashboard and reads the run tree under ./Runs.

python -m Training.ExperimentManager

Open http://127.0.0.1:9000. To choose another run directory or starting port:

python -m Training.ExperimentManager \
  --runs-root /path/to/project/Runs \
  --host 127.0.0.1 \
  --port 9000
The service is optional.Training writes its SQLite record locally and continues if the HTTP service is absent or temporarily unreachable.

3. Run the included experiment

python main.py

The sample downloads MNIST through torchvision, trains SampleCNN, then evaluates the best checkpoint. It therefore needs network access on its first run and may use the detected CUDA device.

4. Inspect the run

Runs/
└── MNISTSampleDataset/
    └── SampleCNN/
        └── sample_cnn_baseline/
            ├── best.pth
            ├── last.pth
            ├── comments.txt
            ├── model_arch.txt
            └── status_and_log.sqlite

TensorBoard event files are added only when enable_tensorboard is true. The SQLite file is the Experiment Manager's durable record for metadata, scalars, and figures.
